# tools/machine/

Scripts d'installation et de contrôle de l'espace `Work/` sur une machine. Ils ne modifient jamais la configuration home (`~/.gitconfig`, `~/.ssh/`) et ne commitent ni ne poussent rien. Les lancer depuis la racine `Work/` (`WORK_DIR` pour viser un autre espace).

| Fichier | Rôle |
|---|---|
| `install.sh [--brain URL] [--brain-perso URL\|new] [--no-bootstrap]` | Point d'entrée après le clone de `Work` : clone le brain privé (`--brain <url>`) ou en crée un vierge depuis `kit/brain/seed/` (`tools/brain/new-brain.py`), `brain-perso/` en option (`--brain-perso <url\|new>`), renomme le remote Work-Starter en `starter`, puis lance `bootstrap.sh` (sauf `--no-bootstrap`). Relançable sans rien écraser. Les autres brains (`brain-<nom>`) se créent avec `new-brain.py` ou se clonent à la main. |
| `bootstrap.sh` | Prépare un checkout neuf : clone `brain/` depuis `BRAIN_REMOTE` (obligatoire) quand `brain/` n'est pas encore un dépôt Git, installe les hooks Git dans Work et dans chaque brain présent, crée `repos/`, `agents/` et `artifacts/`, puis valide la configuration, écrit le lock, installe les skills tiers (`npx`, seulement s'il y en a), expose les skills, vérifie les liens et enregistre l'empreinte de la configuration. À relancer après l'ajout d'un brain pour y installer les hooks. |
| `update.sh` | Refait la partie skills de `bootstrap.sh` (validation, lock, installation des skills tiers, copies, liens, contrôle des liens, empreinte) puis signale l'état Git de Work et de chaque brain (branche, commits non poussés), sans pull, commit ni push. À lancer après un `git pull` de Work ou d'un brain qui change la configuration. |
| `work_config.py <commande>` | Résout la configuration des skills : défauts publics (`work-config.example.json`), puis `.data/work-config.json` de chaque brain, puis `work-config.local.json` ignoré (la dernière couche l'emporte ; les noms désactivés s'additionnent). Commandes : `check` (valide), `list-brains`, `list-own` (nom, brain, `link` ou `copy`), `list-third-party` (activés), `list-catalog` (tous les skills tiers connus), `lock` (écrit `skills-lock.json`, refuse s'il liste des skills qu'aucune couche ne connaît), `adopt [--brain B]` (enregistre ces skills dans le `.data/work-config.json` du brain B, `brain` par défaut), `stamp` (écrit `.work-state.json`), `status` (code 1 si la configuration a changé depuis le dernier `stamp`). |
| `link-skills.sh` | Expose aux agents les skills activés : liens `.agents/skills/` et `.claude/skills/` vers `<brain>/skills/<nom>`, liens `.claude/skills/` vers les skills tiers installés dans `.agents/skills/` ; retire les liens gérés devenus inutiles et met de côté (`.agents/skills-disabled/`) les skills tiers désactivés. |
| `sync-house-skills.py [--check]` | Copie dans `.agents/skills/` et `.claude/skills/` les skills de brain marqués `.install-as-copy`, et retire les copies obsolètes ; `--check` ne change rien et échoue si une copie manque ou est périmée. |
| `check-links.sh` | Lecture seule : configuration, liens et copies de skills, puis `tools/brain/check-links.py` sur chaque brain (un lien inter-brains échoue). À lancer après un déplacement. |
| `doctor.py` | Diagnostic local en lecture seule, sans réseau : commandes requises, brains attendus (`brains` de `brain/.data/local-paths.json`), état Git de chacun, frontière déclarée dans `.data/brain.json` (champs renseignés, `remote` et `email` effectifs conformes aux motifs), fichiers `.data/*.json`, dossiers d'entrée, configuration des skills (couches valides, changée depuis le dernier `update.sh`, skills installés mais non adoptés, skills tiers non installés, liens cassés ou orphelins) et nombre de fichiers des artifacts non sauvegardés. Code 1 s'il trouve une erreur. |
| `hooks/` | Hooks installés par `bootstrap.sh` : `work-pre-commit` (secrets dans les ajouts stagés de Work), `brain-pre-commit` (sur l'index d'un brain : actions mal rangées ou mal formées, liens morts et liens vers un autre brain, noms de clients d'un autre brain, secrets), `commit-msg` (Conventional Commits, aucune mention d'IA) ; `check-staged-secrets.py` et `check-commit-msg.py` portent les contrôles. Ils valident sans jamais écrire. |
| `check-no-client.sh [--staged\|--worktree]` | Scan manuel facultatif de ce dépôt (par défaut l'arbre de travail) : cherche dans les fichiers publiables les noms de clients et de personnes connus du brain par défaut. Ne certifie rien. |
| `check-no-client.py --brain DIR --staged\|--worktree` | Scan d'un brain contre les noms de clients des autres brains de l'espace, sauf ceux de la liste `allow` de son `.data/brain.json` ; lancé par le hook `brain-pre-commit` sur l'index. Sans `--brain`, même scan que le `.sh`. |
| `gitconfig.example` | Modèle de `~/.gitconfig` avec une identité par frontière de confiance, à recopier et adapter soi-même. |
| [`GIT-IDENTITY.md`](GIT-IDENTITY.md) | Règles d'identité Git et SSH par frontière de confiance (clés, `includeIf`, vérification de l'auteur, de la clé et de la clé d'hôte) : à lire avant toute écriture distante ou premier clone. |

Fichiers générés et ignorés par Git : `.agents/` et `.claude/skills/` (skills exposés aux agents), `skills-lock.json` (skills tiers activés) et `.work-state.json` (empreinte de la configuration résolue, comparée par `doctor.py` et `work_config.py status`).
