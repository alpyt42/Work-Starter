# artifacts/ — outputs for humans

> Files produced **to be seen by someone**: decks, one-pagers, Office documents, PDFs, exports, diagrams, mockups. Neither code (→ `repos/`), nor working context (→ a brain), nor agent scratch (→ `agents/`).

This covers real deliverables (a deck, a one-pager) **and** working artifacts that are delivered to nobody but remain documents (a diagram, an HTML summary page) **and** source material received from a client or a third party when it is large (an Excel file, a PDF, a screenshot). The criterion is not "who made it", but "is it a big binary that has no business in a Git history" (see below).

## Structure

Grouped **by project first**, then one folder per artifact:

```
artifacts/
├── <client>/                   # one folder per client, flat
│   └── <artifact-slug>/
│       ├── README.md           # provenance: where it comes from, what it is for, how to rebuild it
│       └── …
└── internal/                   # whatever has no client
    └── <project>/
        └── <artifact-slug>/
```

Each artifact folder carries a provenance `README.md` — without it, six months later you find a 4 MB `.pptx` that nobody knows is up to date or how to regenerate. Minimum: **what** (one sentence), **use** (for whom, sent when), **provenance** (generated by what, from which note, on which day), **maintenance** (how to redo it).

## Build files live in `agents/` or a repo

What stays here are the deliverables meant to be read by a human and their provenance README. Build plans, scripts and intermediate renders live in `agents/<project>/<session>/` during production. If a generator must be kept and reused, promote it to a suitable repo. The artifact's README says where to find its source while it exists; do not edit the output by hand when it can be regenerated.

## Artifacts are not versioned

Apart from this README, the content of the folder is ignored by Git: files can be heavy and binaries do not diff. The memory keeps the pointer (the project page mentions the artifact and its path). A generator kept long term is versioned in a repo; in `agents/`, it stays disposable. If you want a backup of the deliverable, use a suitable storage location, not this Git repository. Only the owner removes anything here: an agent never deletes an artifact, even one it produced; it may only move one into an `archive/` folder inside `artifacts/`.

**Received source material** (Excel workbook, PDF export, screenshot sent by a client): same rule — it goes here, not in a brain (versioned in Git, not made to carry binaries). The text extracted from it (analysis, figures, notes) stays in the relevant brain as `.md`, with a link to its matching `artifacts/` folder.

⚠️ **Client content**: an artifact that contains a client's data or context is never published outside (web page, third-party service, shared artifact) without an explicit request for each piece.
